# resolved SS μμ nonprompt 추정 — MC 검증 메모 (2026-09-24)

**범위**: 2024 MC 만 사용. 실제 데이터는 읽지 않았다 (condor 목록, skim 스크립트, 분석 로더 모두 EGamma/Muon 을 거부).
이 메모의 결론은 **MC feasibility 와 fit 설계 검증**이다. fake rate 는 MC seed/validation map 이고,
**data calibration 은 하지 않았으므로 data-driven 추정이 완료된 것이 아니다.**
v3 카드·원본 결과는 건드리지 않았다. 모든 산출물은 이 폴더(`studies/nonprompt_ssmm/`)와 `plot/cutbased/out/nonprompt_ssmm/` 에만 있다.

표기: `iso-TT/TL/LT/LL` = isolation category (T: TkRelIso<0.1, L: ≥0.1, lead/sub pT 순).
`TTLJ`, `TTLL` = **샘플** 이름 (ttbar). plotter 그룹 "Nonprompt"(TTLJ+W+jets+ST s/t)는 **샘플 라벨**이지 truth 가 아니다.
truth 는 muon 별 P/F/U (아래 §3).

## 2. 선택·tree 확인 (요청 1)

- **`Central_SR_LL_MM_BDTTree_resolved`(presel) 의 "LL" 은 "두 muon 모두 fail" 이 아니다.** 실제로는 "loose 두 개 + 적어도 하나 not-tight" = TL+LT(+원래는 LL) 의 합이며, `n_loose_leptons==2` 를 요구한다.
  반면 TT 가 들어가는 `SR_MM` tree 는 loose 개수 제한이 없다 → **두 tree 의 FO 쌍 정의가 달랐다.**
- **LL 누락**: presel 의 `if (n_leptons<1) return;` (n_leptons = tight 수) 때문에 tight 가 0 인 LL 사건은 저장 전에 버려졌다. 기존 표의 LL=0 은 선택의 결과가 아니라 이 gate 때문. HNWR FOMode 는 이 문제가 없다 (FO 블록이 tight 요구 앞에 있음).
- **boosted routing**: HNWR FO 블록은 resolved/boosted 판정 이전에 독립적으로 채워지므로 boosted 로 빠지는 fail 사건은 없다 (SR 과 같은 resolved 조건만 요구).
- **baseline**: 사건에 FO lepton 이 정확히 두 개 (둘 다 muon, FO 전자 없음). 이 조건에서 FO 쌍 = HNWR 의 T 쌍 (iso-TT 일 때).
  HNWR SR 은 "tight 정확히 2 개" 만 요구하므로 추가 L lepton 이 있는 SR 사건이 있다: presel 로 잰 제거율 OS 1.45%, **SS 16.4%** (WZ 등 3-lepton). FO baseline 은 이 사건을 빼고 있음 → 데이터 단계에서 SR 정의(추가 loose lepton veto 여부)와 AR 정의를 같이 정해야 한다.
- **중복**: 한 사건은 FO tree 에 한 번만 (fillNtuple 1 회), category 는 isolation 두 비트로 배타적. 검증: TT(FO) = presel SR_MM(nLoose==2) 사건 수·weight 정확히 일치, TL/LT(FO) = presel SR_LL 정확히 일치 (WR4000N200 smoke).
- **validation** (`results/01_validate_fo.txt`): 같은 job 의 `SR_Resolved_MM_{OS,SS}_mlljj` 적분 = v3 카드 입력 파일 적분 (분할 샘플 p00–p19 합 포함) → 1.00000 (예외: `TbarBtoLNu-s-channel` 1.069, 0.004 events).

## 3. truth 정의
- P: origin 1 (prompt μ) 또는 2 (prompt τ→μ). F: 3 b 직접, 4 b→c, 5 c, 6 nonprompt τ, 7 light. **U**: 0 (gen μ 없음, ΔR 보완도 실패) 또는 8.
- **unmatched 를 자동으로 fake 로 두지 않았다.** NanoAOD genPartFlav=0 인 muon 중 일부는 ΔR 보완으로 prompt(1)·b(3,4,5) 로 복원된다 (SS noQCD: mu2 7339 raw 중 ~270).
- U 만 있는 iso-TT (F 없음) 은 SS High 1.11, Low 4.41: W+jets 44%, TTLJ 29%, DY 18%, pT 중앙값 300–600 GeV, 0.3 안에 gen μ 가 전혀 없음 → punch-through / decay-in-flight 로 보이나 **확정 못 함**. closure 는 target F 와 F+U 둘 다 보고.

## 10. Asimov 동시 fit 시제품 (요청 6) — `fit/*/card.txt`, `results/06_asimov_fits.txt`, `fit/r_summary.png`
**설계** (`scripts/make_asimov_cards.py`):
- channel: SS × {iso-TT, TL, LT, LL} × {Low 800–1600 (4 bin), High ≥1600 (4 bin)} — 겹치지 않는 mass channel, Full 과 Low 를 이중 관측으로 쓰지 않음.
- process: `sig` (8 channel 전부, 공통 r), `prompt` (truth PP, lnN 10% + λ), `undet` (U, lnN 50%), `np_PF`, `np_FP`, `np_FF`.
- nonprompt 응답: leg 별 fake 이면 T: K, L: (1−K f̄)/(1−f̄); prompt 이면 T: λ, L: (1−λ ē)/(1−ē). FO 수가 보존되므로 window 별 자유 정규화 N_Low, N_High 가 fail category 로 정해진다.
  K_Low = `k_Low` (calibration prior σ=7.3%, Low closure map 오차), K_High = k_Low·`tau` (transfer prior σ=16.5%, High closure 의 non-closure ⊕ stat), λ prior 2%.
- **모든 category yield 를 무제약으로 풀지 않는다**: rate 자유도는 N_Low, N_High 둘뿐, 나머지는 response + prior.
- **이중 사용 없음**: fail category 관측은 fit channel 로만 쓰고 고정 template 를 만들지 않는다.
- LL 과 prompt eff 를 생략하지 않고 전부 넣었다 (생략 시 영향은 §8: 1.5% / 0.4%, +QCD LL 4.5%).
- template 의 음/0 bin 은 1e-6 으로 보호 (template 수준, rate clip 아님; card 별 16–21 bin, `info.json` 에 기록).

**결과** (noQCD; r ± 68%; 모두 status 0, covQual 3):

|---|---|---|---|---|
| WR3000 N200 | 0.000 −0.006/+0.018 | 1.000 −0.105/+0.112 | 1.008 | −0.004 / **0.901** |
| WR4000 N200 | 0.000 −0.068/+0.178 | 1.000 −0.339/+0.404 | 1.028 | −0.047 / **0.758** |

- nuisance (fit_s): k_Low 1.000±0.069 (prior 0.073 → 거의 제약 안 됨), **tau ±0.16 = prior** (fail category 는 transfer 를 제약하지 못함 → closure 에서 정한 prior 가 곧 이 systematic), λ 1.000±0.012 (prior 0.02 보다 좁음: LL/LT 의 prompt-L 로 제약), N_Low ±8%, N_High ±18–25%.
- **misHigh** (가짜 데이터의 High fake rate 를 30% 올림, prior σ 16%): r bias +0.3–11% — fit 오차 대비 작다. tau 는 거의 당겨지지 않는다 (1.005–1.016).

## 12. 사용 가능한 calibration 영역 / 필요한 transfer 불확실성 / data 단계 검증

**MC 로 본 결론**
1. **iso-TT 를 뺀 fail category (TL/LT/LL) 의 SS low window** 는 signal 오염이 ≤2.5% 로 작아 nonprompt 조성 확인에 쓸 수 있다. 그러나 이것은 **SR 안의 부분 영역**이고, iso-TT low window 에는 WR3000N200 이 26% 있다 → low window 를 "signal-free CR" 로 확정할 수 없다. 동시 fit 에 signal 을 모든 category 에 넣는 방식이 필요하다 (fixed template 은 mN=200 에서 최대 65% bias).
2. fake rate 자체는 이 SR-인접 영역에서 **측정하지 말고** (signal·prompt 혼입), 별도 측정 영역 (아래) 에서 재야 한다. 이 스터디의 map 은 MC seed.
3. transfer (low→high) 불확실성: MC closure 기준 **~16% (noQCD) / ~19% (+QCD)** — 대부분 High target MC 통계 (±15%). pT>300 GeV 구간 extrapolation 은 별도 (MC 로 ±40% 수준, §6).
4. LL 과 prompt-eff 는 noQCD 에서 무시 가능하나, QCD 가 실제로 있다면 LL 항 (~4.5%) 은 반드시 넣어야 한다 (FF 음의 항).

**data 단계에서 필요한 것**
- fake-rate 측정 영역 (data): single-muon + away-jet (b-tag 로 b 농축), MET/mT 로 W 억제, prompt 오염을 MC 로 차감. HNWR 에 없는 영역이므로 analyzer 추가 필요. 측정 영역의 fake 조성 (b 직접 vs b→c vs c vs unmatched) 이 SR fail category (b 직접 ~74%, U ~9%) 와 맞는지 MC truth 로 먼저 확인.
- pT binning: 53–60 / 60–80 / 80–120 / 120–200 / 200–300 / 300+, |η| 0–1.2 / 1.2–2.4. 300+ 는 측정 통계와 별도 systematic.
- 데이터 closure: SS low window 의 TL/LT/LL 과 OS 영역을 VR 로 (unblinded 가능한 쪽만), W+jets/ttbar 농축 VR.
- U (gen μ 없음) 성분의 성격 규명 (punch-through / DIF): data 에서는 구분 불가하므로 fake rate 측정 영역에 같은 비율로 있는지가 관건.
- SR 정의 정합: HNWR SR 은 추가 loose lepton 을 veto 하지 않음 (SS 에서 16% 차이). data-driven AR 과 SR 의 FO 사건 정의를 통일할 것.
- 카드의 W+jets 세트 문제 (§11) 해결 후 nonprompt 총량 재평가.
- blinding: SR iso-TT data 는 fit 단계 전까지 열지 않는다. fail category data 도 SR 안이므로 blinding 정책 확인 필요.

**조정 기준**
- 기대 pull: 데이터 k ≈ 1.27–1.33 이면 lnN 2.0 에서 +ln(1.3)/ln(2) ≈ **+0.38σ** 부근이 정상.
